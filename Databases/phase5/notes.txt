Phase 5: Prisma: Prisma is a TypeScript/JavaScript ORM (Object‑Relational Mapper).
                    Think of it as a translator between your Node.js/Express code and our database (Postgres, MySQL, MongoDB, etc.).

                    Instead of writing raw SQL queries, we write JavaScript/TypeScript code. Prisma then:
                        Converts that code into actual SQL queries.
                        Runs those queries against the database.
                        Returns results back to your backend functions.

    Prisma = 3 Main Pieces:
        1. Prisma ORM: The whole toolkit/framework. Includes schema, migrations, client, etc. [ex= car]
                            schema.prisma: Defines our application/database model.
        2. Prisma Client: Auto‑generated JS/TS library we import in our code. We call methods like "prisma.user.findMany()"
                                Lets Node.js interact with the database without manually writing SQL for every CRUD operation.
        3. Prisma Migrate: Tool that turns schema changes into SQL migrations and applies them to the DB.
                                Converts schema changes into migrations/SQL.


    Here’s what happens behind the scenes:

        1. we call "prisma.user.findMany()"     - (in backend express controller)
        2. Prisma Client translates that into SQL:              
                SELECT * FROM "User";
        3. Database runs it, returns rows.
        4. Prisma Client maps rows into JS objects and gives them back to our controller.


    Schema & migrations:
        1. We define our models in schema.prisma (like User, Post, etc.).
        2. Run prisma migrate dev → Prisma generates SQL migration files and applies them to our DB.
        3. This keeps our database structure in sync with our code.

The most important thing:
    Prisma does NOT replace MySQL/PostgreSQL.
    Prisma is an ORM/tooling layer that helps your application work with them.

What Prisma is actually doing

    Suppose you write:
        await prisma.user.findMany({
        where: {
            age: 25
        }
        });

    You don't normally write:
        SELECT * FROM users WHERE age = 25;

Prisma translates your operation into database-specific SQL and sends it to your database.

    Conceptually:
        JavaScript
            ↓
        Prisma Client
            ↓
        SQL generation
            ↓
        PostgreSQL/MySQL

"npx prisma db pull" = If we already have a db & we want Prisma to understand that existing database.

        Existing DB
            ↓
        Prisma introspection
            ↓
        schema.prisma

"npx prisma db push" = It synchronizes your Prisma schema with the database without creating the normal migration history we'd use for production migrations.

        schema.prisma
            ↓
        database


migrate dev     vs      db push

Command:	                    Purpose:
prisma migrate dev	        Development migrations + migration history
prisma db push	            Quickly sync schema → DB
prisma db pull	            DB → Prisma schema
prisma migrate reset	    Destroy/reset DB and replay migrations
prisma generate	            Generate Prisma Client
